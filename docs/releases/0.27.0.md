# 0.27.0: a session out of its usage limit reads as one that cannot read (hub 0.27.0, plugin 0.24.0)

Effects first: three new session columns, added in place; no client breaks; a new hook event and a new event frame.

- **Why:** a main seat whose session had hit its usage limit showed as connected; a send said "delivered, connected"
  and the answer waited five days unread. Nothing told the sender or the person (the suite owner's request, from Max).
- The plugin now listens to Claude Code's StopFailure hook. A turn that ends on a usage limit or an account error tells
  the hub, with the error line; the hub reads the reset time from it when the line names one.
- While it lasts, presence says "cannot read until <time>"; a send to a role it holds counts as nobody reading, with
  who else is in the room; health counts that mail as unread by nobody, with the cause; the plugin's wake-up hands
  it nothing (the mail stays unshown for when it can read).
- Its person gets one push per main seat and limit window, never per message.
- Any later hook that shows the session working ends the state; at the reset the hub ends it and wakes the session.
- No seat moves because of it: only the session itself can say it, and a peer who is not main must not inherit main's
  mail by order of arrival. Another session of the person takes the seat with `claim_role main` when that is wanted.
